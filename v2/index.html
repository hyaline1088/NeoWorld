01

The method

How NeoWorld-3 builds a world.

One figure, taken apart step by step. Keep scrolling: the figure zooms to each stage as you read about it, and the last step plays a real example.

1 · Real observations

Start from what a camera sees.

A handful of RGB-D photos of a real place, each with its camera position. Here: an office coffee corner.

2 · Scene agent

One agent owns the whole scene.

It looks at the photos, measures what it needs, and writes the scene as a program: boxes, cylinders and where they go. Then it keeps revising that program.

3 · NeoMCP + NeoSDK

Tools to build, measure and refine.

NeoMCP gives the agent its tools: read, edit, measure, refine. NeoSDK does the geometry. Many candidate fits are tried in a fast GPU copy of the program, and a strict harness decides what is kept.

4 · Object handoff

Hard objects get a specialist.

An object that needs more care, like the coffee machine, is handed over with its own evidence: the views that see it, its current source, and the objects around it.

5 · Object specialists

Write, fit, compare, repeat.

The specialist writes a fresh program for that one object, fits it to the photos, and compares real and rendered views from the same cameras. If they disagree, it revises the code or refits the numbers. Cameras and neighbours stay fixed.

6 · Parent integration

Kept only if it is better.

The returned object is tried in a copy of the scene and checked: geometry, who owns what, and whether it really improves the match. If not, the scene stays as it was.

7 · Real–sim scene

An editable scene that matches the photo.

The result is rendered from the same camera as the real photo. Whatever still differs goes back to the scene agent for another round.

8 · Articulation

Parts that move get joints.

Joints are declared in the code, swept through their range to catch collisions, and exported as URDF. Axes and limits the photos cannot confirm stay marked as unresolved.

The whole loop

From photos to a world a robot can use.

Observe, build, check, refine, and hand the result to a robot, with feedback at every stage.

02

A world written as code

Keep the recipe, not just the cake.

Most 3D methods predict a finished surface in one step. NeoWorld-3 keeps something more useful: the program that builds the object. Change one number in it and every part that depends on that number follows.

P = (S, θ, T)
S · sourcethe Python program that builds the parts
θ · knobsnamed, bounded numbers such as a leg length
T · placementwhere each object sits in the scene

The result is exported as URDF, the standard file robots and simulators read: links, joints, axes and limits. Drag the divider over the chair below to look underneath its surface.

03
Reasoning meets gradients
The agent sketches. The optimiser measures.

        

          
Language models are good at structure (“a chair with four legs and a tilted back”) but poor at exact numbers. So NeoWorld-3 splits the work. The agent writes the program; an optimiser then tunes its named knobs until renders match the photos.


Because the optimiser moves a few meaningful knobs rather than thousands of points, one leg_length keeps all four legs equal.
